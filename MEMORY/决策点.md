# 决策点

## 视觉方向
- 放弃「明亮作品集/玻璃拟态/渐变 SaaS 落地页」，改为黑暗混凝土档案馆 + 单色骨白 + 猩红点缀。理由：用户要求「不模板化」，且暗场里的体积光是唯一能同时表达空间与时间的廉价强视觉。
- 房间几何不放进 Blender，全部在 Three.js 程序化生成。理由：全是盒子，代码里改一行就能迭代，走 Blender 每次都要等导出。

## 标本
- 最终材质：冷色钢（color 0.615/0.635/0.665、metalness 1、roughness 0.145、flatShading、不透明）。弃用过的方案及理由见下。
  - 骨白矿石：暗场里只靠点光取亮，读作蜡烛/蜡块
  - 发光红晶：读作岩浆或手游道具
  - 黄铜：与暖光同色相，明暗对比全失，像金块堆
  - 透明玻璃：暗场里没有可折射环境，渲染成奶油色扁盾
- 标本由 6 扇区楔块拼成一根六棱柱，静止时缝隙只有发丝级；点击才散开。理由：早期把缝隙做大会读成「一堆独立石块」，丢失「一整块晶体被打散」的叙事。
- 景深对焦：dof.target 指向标本世界坐标（Vector3 每帧同步），不用 focusDistance。手动值 0.02–0.14 全部对不准。

## 相机与版式
- 四章节机位全部贴近首屏机位，只做小幅前推。理由：给每章独立机位会让标本跑出画面、右侧全空。
- 遮罩（.scrim）压暗只收到 57% 宽度。理由：超过 57% 会把右侧标本压成灰色。
- 雾参数、sun 强度、bloom 阈值是一组耦合值（0.052 / 3.0 / 1.15），单独调任何一个都会让百叶窗变成硬白条。已回退过一轮，不要重复。
- 窄屏取景补偿用 setAspect：aspect 越小越拉远、越收紧 fov 变化（pullBack k*2.15）。

## 性能
- 采用自适应分辨率而非砍效果。实测关掉阴影/景深/色差各只涨 2–3fps，真正的瓶颈是每像素成本。
- **画质必须以物理像素为基准，不能以 CSS 像素为基准**。早期 QUALITY_MAX 上限取 1.75 但初值和下限按 CSS 像素算（1.0 / 0.62），在 dpr 2 的高分屏上相当于把 1166×656 的缓冲拉满 1600×900 显示，用户直接反馈「看不清楚」。现改为：上限 min(dpr,1.75)，下限 max(0.9, min(上限, dpr×0.66))，初值 0.9×上限。宁可帧率降一点，也不能在高分屏上糊。
- 提供手动画质开关（页脚按钮 + ?q=high / ?q=low）。理由：本机测不准用户的 GPU，与其猜不如给出一条用户自己能试的退路。
- 阴影贴图 4096 → 2048（几乎无画质损失，省一点带宽）。

## 工程
- 后处理里 ChromaticAberrationEffect 是卷积效果，必须单独一个 EffectPass。
- 凸包几何 + anisotropy > 0 = 着色器 NaN，经 Bloom 扩散成全屏黑。碎片材质 anisotropy 必须为 0，并给 hull 补 uv。
- Material.clone() 不复制 onBeforeCompile，注入式材质必须走工厂函数。

## 清晰度（第二轮）
- 渲染处理器一律 new EffectComposer(renderer, { frameBufferType: THREE.HalfFloatType })，不传 multisampling。4x MSAA 在集显上的带宽代价远大于一个 SMAA pass；SMAA 固定留在 grade pass 里，不随画质档位开关。
- 像素预算 PIXEL_BUDGET = 6.0e6，RES_CEIL = max(1, min(NATIVE_DPR, 1.75, sqrt(6e6 / (innerWidth*innerHeight))))，onResize 时重算。理由：只按 dpr 定上限会让 4K 全屏把显存带宽吃穿。
- 自适应顺序固定为「先降效果，再降分辨率」：fxLevel 0→1→2 依次关景深、关色差，两级都关完且仍慢才动 res（−0.08）；恢复时反向。慢要连续 2 窗、快要连续 3 窗才动作，每次动作后 2 窗冷却（60 帧一窗）。
- 实测 dsf=1.25 → buffer 2000×1125 = 物理像素 1:1，共 2 个效果全开仍能跑；阶梯轨迹证明先掉 fx 不掉清晰度。

## 视觉收尾（本轮）
- 标本静止态接缝收到发丝级（径向外推 0.0022+rand*0.005，home.y 抖动 ±0.0035）；碎片 roughness 0.34+rand*0.15。白矩形高光是「整面同法线的镜面高光被裁死」，靠粗糙度解决，靠挪灯解决不了。
- 窗洞那片「白栅栏」= 透过百叶缝隙看到的天空发光面（隐藏天空面即消失，改百叶材质无任何变化）。天空面 26×17 米，窗口只占 18%，原衰减在这个尺度上等于常数 → 窗口取到同一个亮度。修法是把衰减按窗口尺度放大（r*7.0）并把峰值压到 1.0 以下，让 ACES 工作在线性段；峰值超过 1.0 再乘任何渐变都会被压平成同一档。
- 左墙顶部冷光灯槽在低机位下是画面左上角一道悬空亮刃，已删除，只留右墙一条。
- 循环里 warmRim.intensity = 7.0 每帧覆盖构造参数，导致之前所有对暖光的降亮改动全部无效。**改灯之前先 grep 循环里有没有每帧赋值。**

## 手感（光标与镜头）
- 自绘光标必须直接跟随：早期用 rAF 里 cx += (mx-cx)*0.16 做缓动，30fps 下等于把光标拖后约 200ms，用户直接反馈「鼠标到网页上速度下滑」。现在在 pointermove 里同步写 transform，零延迟；hover 态仍由 pointerover 切换。
- 相机视差阻尼 lambda：mouseSmooth 3.2→11.0，pos 2.2→6.5，look 2.6→7.5，fov 2.4→5.0。理由同上：原参数在低帧率下像在拖着一块布。

## 自适应阶梯（第二轮修正）
- **默认从清晰端起跳**：fxLevel 初值 1（关景深），让开场就是清晰的画面。实测那是用户「要等一会儿才变清晰」的真因——阶梯在 8～20 秒后才把景深关掉，画面突然变尖，等于把「一开始的糊」暴露出来。
- 自动模式永不把景深加回来（fast 分支只允许 fx 2→1 恢复色差）。想要电影感用「高」按钮或 ?q=high。
- 采样窗口由 60 帧改为 500ms（frameAcc >= WINDOW_MS 且 frameCount >= 12），低帧率下 1 秒内就能收敛；开头 900ms 为 warmup，不计入统计，避免首帧着色器编译的 300ms 卡顿触发误降。
- 慢：连续 2 窗 → 先 fx+1（cooldown 1），fx 到底再 res−0.10；快：连续 3 窗且 avg<14ms → res+0.08，再加回色差。
- 实测（dsf=1.25，Iris Xe）：开场 0.8s 即 fx 1 / res 1.25，1.5s 收敛到 fx 2，全程无分辨率跌落；同机 q=high 只有 20fps（景深约值 10fps，色差约 1fps）。

## 碎裂交互（第三轮重构）
- **弃用冲量爆炸**：旧 burst() 给每块 5.0 径向冲量 + ±2.2 随机 + ±0.10 扭矩，结果点击瞬间是"一堆方糖被炸开"，用户反馈"点一下就模型崩溃"。浏览器侧无 pageerror/无 crash（双 GPU、连点 12 次均正常），所以那是观感问题，不是崩溃。
- 现方案：**解理展开包络**。burst() 只给一次小冲量（1.15×dir + 少量随机），随后每块的目标位置 = home + dir * 0.24 * env，env 由 per-piece 的错峰包络 0→1→0 驱动（rise (burstT−wave)/0.55、fall (BURST_END−burstT)/0.8，BURST_END 2.35s，wave 按高度 0..0.42s 错峰）。弹簧在展开期加硬（k 46 / damp 6.4），静止期回 34 / 4.2。没有翻滚、没有漂移，所以收得回原位、也读作"沿解理面被震开"而不是"碎成一堆积木"。
- **精确归位**：展开结束后（burstT 走完）统计所有碎片到 home 的最大偏移，< 0.075 且持续 0.16s 就把每块 setTranslation(home)/setRotation(identity)/清速度，并同步 mesh。实测点击后 3.4s：settled=true、maxOff 0.03（剩下的偏移是指针磁力）、四元数 w=1（姿态精确复原）。
- 片数 30 → 89：切割步长 0.17 + rand*0.085（每扇区 15~18 片）。片多才不像积木。
- 静止态缝：竖向 geo.scale(1.0, 1.012, 1.0) 让上下片微量重叠（封死发丝缝），径向外推降到 0.0004 + rand*0.0012，sector 边界不再收窄（原 0.996 会在每 60° 留一道竖沟，读作"编织物"）。
- 逐块随机色调是"拼接感"元凶：tone 0.88+rand*0.24 → 0.985+rand*0.03，roughness 0.30+rand*0.06，iridescence 固定 0.10，基材 roughness 0.40、envMapIntensity 1.0。
- 内胆（红色六棱柱）永久 inner.visible = false：它正是静止态那些红色发光线缝/内部红光斑的来源之一，展开时也不需要露出来。
- 碎片仍是金属材质（metalness 1）——暗场里只有金属的高光对比能读出多面体形体，这一点不接受替换。

## 测试方法（重要教训）
- **headless Edge 默认走集显**。不加参数时 getStats().gpu 是 "ANGLE (Intel, Intel(R) Iris(R) Xe)"，没法验证独显表现。今后 3D 测试一律加 `--ignore-gpu-blocklist --force_high_performance_gpu`，读到 "ANGLE (NVIDIA, NVIDIA GeForce RTX 4050 Laptop GPU… D3D11)" 才算数。
- 实测（1600×900，dsf1.25，?q=auto）：独显 60fps / res 1.25 / fx 1；集显 55fps / res 1.25 / fx 2（自动关掉色差）。8 次连点后均无 pageerror、无 crash。
- 用户报"崩溃"时先分证：pageerror + crash 监听、连点压测、数值探针（NaN/maxOff）三件套，确认是渲染观感再改画面。

## 首帧"卡死"的真因与修法（2026-10 第四轮）
- 现象：用户报"打开没多久直接卡死"。空页对照无卡顿，三档画质（high/auto/low）、集显与独显都会卡 → 与画质档、GPU 无关。
- 定位手段：addInitScript 挂 PerformanceObserver longtask + rAF 帧间隔打点（tools/probe-timeline.mjs），并在 main.ts 里临时插入 `__mk` 时间戳。
- 结论：**所有成本都压在第一次真正出图的那一次 `composer.render()`**，与分辨率几乎无关。同一跑分里 240×150 渲染 4606ms、第二次 10ms、主分辨率首帧 4ms。`renderer.compile()` 只有 27ms —— three r152+ 的 compile 走并行编译，链接/管线创建推迟到首次 draw，所以提前 compile 并不能避开这笔钱。
- 分解（生产包，Iris Xe）：渲染器 70ms → createMaterials 745ms → 三个 PMREM 环境 1000ms → 房间/光柱/尘埃/标本 ~70ms → 后处理搭建 ~12ms → 首帧渲染 4600ms。合计约 7s，全部同步阻塞主线程。
- 修法：`warmComposer()` 先把 `composer.setSize(240,150)` 跑两遍再 `applyRes(resScale)`，把这笔一次性的管线创建从主分辨率上挪走；遮罩留到 `__FRAMES__ >= 4` 才收；预加载条加一条纯 CSS 的 `.pl-sweep` 动画（transform，跑在合成器上，主线程被占住时照样动）；`body.is-loading` 改由 index.html 内联脚本立即加上，保证首帧就被锁住。
- 效果：首发长任务 10064ms → 960ms（生产包、Iris Xe）；开发服模块图执行本身 3635ms + 预热 905ms，两者都在遮罩之下，页面从 435ms 起就画着加载界面。
- 教训：**"卡死"要先分清是哪一段在阻塞**。空页对照 + 分阶段时间戳 + longtask 观察器三件套，比换参数猜要快得多；也不要相信 `renderer.compile()` 能把 shader 成本提前付掉。

## 标本观感以"首版"为准（2026-10 第五轮）
- 用户诉求（原话）："我还是更喜欢第一版的模型样子，现在的就没有第一版的惊艳感了，能不能做到在保留现有优化的前提下达到第一版的效果？"
- 认定"第一版" = shots/121-hero.png（骨白矿石材质 + 约 30 块粗解理碎片 + 黄铜双环 r0.86/0.64 + 景深）。关键事实：**首版根本没有 solid 整块网格，静止态就是碎片常显**；后来为解决接缝和性能才引入"静置显示 solid"，把 facet、缝内红光、环的层次一起弄没了。
- 恢复做法：碎片常显（mesh.visible=true）、solid 仅作退化备份；切割步长回到 0.46+rand*0.26（约 34 块）；基材回到骨白矿石（color 0.760/0.700/0.615、metalness 0、roughness 0.32、clearcoat 1、envMapIntensity 0.62）；碎片用 stoneMaterial 注入程序化噪声；黄铜环加粗到 tube 0.034/0.026 并提亮（envMapIntensity 1.42）；标本放大到 scale 0.78（竖屏 0.62）；弹簧加硬到 42（爆发 46）。
- **踩坑**：main.ts 预编译块的 finally 里残留旧约定 `pieces.forEach(...visible=false); specimen.solid.visible=true`，会静默覆盖"碎片常显"，表现为改了都没反应。排查靠 probe 打印 {solidVisible, pieceVisible}。
- 景深定夺：景深会把整帧柔化（bokehScale 1.35 时标本发灰），且与用户反复投诉的"糊/要等变清晰"直接冲突。**fxLevel 默认一律 1（关景深）**，不论集显独显；电影感景深只在「画质：高」或 ?q=high 下开启。

## 标本重构：Voronoi 解理 + 磁吸重组（2026-10 第六轮）
- 用户原话纠正："第一版有 89 片解理碎片，点击之后这些碎块会像磁铁一样吸附上去" —— 目标因此从"包络呼吸"改成"碎裂 + 磁吸归位"。
- **碎片必须用 Voronoi 胞**：新增 src/world/voronoi.ts（clipPolyhedron / facesToGeometry / voronoiCells）。随机凸包拼不严（缝隙大、读作碎石堆），只有 Voronoi 能同时满足"每块凸壳可当 Rapier collider"和"静止态严丝合缝"。CHUNKS = 88，种子按体积均匀撒 + 最小间距拒绝。
- **facesToGeometry 返回绝对坐标**，mesh.position 又是质心 → 必须先 `faces.map(f => f.map(v => v.clone().sub(centre)))` 再建几何，否则碎片被二次位移、炸成鹅卵石。
- 物理三段式 phase = 'rest' | 'scatter' | 'pull'：
  · burst() **直接 setLinvel/setAngvel**，绝不用 applyImpulse —— body.mass() 在首次 world.step() 之前读到 0，冲量会被静默丢弃（曾导致"点击后碎片完全不动"，探针 maxOff 恒为 0）。
  · scatter 0.42s（初速 1.15+rand*0.55、切向 0.18 造旋涡、上下 ±0.24 扇形、角速度 ±1.35）；pull 段 k = (6.0 + 2.6/(d²+0.0042)) · ramp、damp = 2.05·√(k+0.5)·0.92、力上限 190，d<0.15 且 ramp>0.5 触发 capture（easeOutQuint + slerp，CAPTURE_TIME 0.17）。
  · 全程 gravityScale 0、linearDamping 1.35、angularDamping 3.4、density 0 + setAdditionalMass(1.0)；分相位避免穿模：pull 前开互碰 + CCD，capture 后 collisionGroups 置 0 由代码归位。
  · 实测：88 片 1.2–1.5s 全部归位、maxOff 0.003、无 pageerror。
- 点击反馈只保留**一次镜头微震**（burstAge 驱动 0.62s 衰减）。曾加过扩散冲击波环，在象牙色晶体上几乎看不见，已删。
- **暗场里金属面只反射环境**：metalness=1 而环境是黑的，每个晶面就是同一个灰值 → 多面体塌成一张纸。必须换**渐变棚环境**（env.ts 用 canvas 画等距柱状渐变 + 顶棚柔光箱 + 一暖一冷竖亮条，PMREM 输出）。改完晶面才靠法线朝向分级，形体才"刻"得出来。
- 最终材质是**象牙骨质**而不是钢：color (0.760,0.735,0.685)、metalness 0、roughness 0.30、clearcoat 0.65、envMapIntensity 0.85、iridescence 0.16、flatShading、transparent false、polygonOffset 1.4/1.4；再注入菲涅耳棱光（uFres 0.30/0.36/0.46，指数 3.2）读作"透明晶体的边"。理由：灰钢在灰墙前直接消失，象牙色在纯黑里才立得起来（与参考视频里的象牙雕塑一致）。
- 静止态接缝 geo.scale 0.9982：叠压（1.0018）会在面上留白色碎点，更小的缝又让背景光透成"虚线贴纸"。
- 展台换成圆形黑石（plinthBase/Cap/Ring 三个件，name='plinth'），**竖屏收起展台**（近处会变成占满下半屏的黑鼓并压住文案），标本浮在虚空里。
- 百叶 slatMat 必须是 `MeshBasicMaterial({ color: 0x060607 })` 纯黑剪影 —— 金属叶片会把天光反成灰色条形码；天空亮度最终 `col *= 0.10 + g * 1.35`。
- 环境亮度定了画面下限：`buildSpecimen(M, artefactEnv, crystalEnv)` 的第二个参数才是碎片用的渐变棚环境。

## 渲染管线大修：IBL / 着色器编译 / 晶体扭转（2026-10 第七轮）
- **裸 CubeTexture 不能直接当 envMap**：three r186 的 getIBLIrradiance / getIBLRadiance 对非 CUBE_UV 映射直接 return vec3(0.0)，等于 ior / roughness / iridescence / envMapIntensity 全在乘 0，晶面只剩 direct light → 多面体塌成平板。CubeCamera 烘完必须过 PMREMGenerator.fromCubemap()（见 main.ts 的 bakeSpecimenReflection）。
- **renderer.debug.checkShaderErrors 默认 true**，program 首次使用时同步等 getProgramInfoLog，冷启动能吃掉 13–16s。生产必须 renderer.debug.checkShaderErrors = !!(import.meta as any).env?.DEV。
- **composer 必须 frameBufferType: THREE.HalfFloatType**：RGBA8 会把 >1.0 截断，BloomEffect 的 luminanceThreshold 1.18 永远达不到，泛光实际失效。
- **RectAreaLight 是着色器编译炸弹**：4 盏矩形灯让每个受光材质多一整套 LTC 积分循环，首帧编译 8.9–12s。已把 warmRim / coolKick / kissTop 换成等效 SpotLight，只保留 edgeRim 一盏矩形灯；首帧降到 3.2s。
- 预热路径：compileAsync 必须在**小尺寸 HalfFloat RenderTarget** 上跑（renderer.setRenderTarget(warmRT)），否则会编出整套 srgb 画布变体而 composer 用 srgb-linear，约 1/4 是死变体。
- 生产包连开三次实测（RTX 4050，1600×900 dsf1.25）：ready 3226 / 2057 / 2063 ms，最长单次 longtask 67–69ms。
